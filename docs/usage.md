# Analyst workflow

1. Start the backend and frontend using [README](../README.md). For the
   synthetic example, start the loopback fixture separately.
2. Create an assessment. Enter the authorized target, exact allowed hosts,
   excluded hosts/paths, and a written authorization statement. Default mode is
   PASSIVE. Choose SAFE_HTTP deliberately for network collection.
3. For the bundled demo, use `http://127.0.0.1:9998`, allow only `127.0.0.1`,
   exclude `/admin` and `/payments`, and enable private-network collection.
   Leave DNS off for this IP-literal target. Set a small request budget/depth.
4. Validate the target. This checks policy without traffic and changes DRAFT
   to READY. Click Discover to run bounded HTTP collection. Inspect coverage
   errors and limit events even when status is COMPLETED.
5. Inspect Attack Surface, Endpoints, Technologies, HTTP Transactions and
   Security Controls. External nodes are inventory references, not fetched
   resources. Forms and API methods can appear without being executed.
6. Add a manual endpoint or import `fixtures/api/openapi.json` in Endpoints.
   Importing creates inventory only. Remote/file refs are rejected.
7. To exercise test-only disclosure and CORS, configure `/.env`, `/.git/`,
   `/debug` and `/cors` as safe paths and explicitly confirm Safe checks.
   The optional origin probe uses only `https://webscope.invalid`.
8. Open a finding. Read **Why WebScope flagged this**, then inspect source
   evidence and the original request/response. Set analyst status, write a
   conclusion, add notes, and explain any severity/confidence/priority change.
   Analyze can be rerun offline; it never contacts the target.
9. Create a case, assign an analyst/priority, link findings and evidence, and
   add notes. Progress OPEN → INVESTIGATING → REMEDIATION → VERIFICATION →
   CLOSED. Cases can move back for further investigation.
10. Generate Markdown, complete JSON, PDF and four CSV datasets in Reports.
    Reports are frozen, hashed database artifacts. Review before sharing.
    Archive completed assessments before permanent deletion.

Settings stores defaults for new assessments, not a hidden authorization
bypass. Each assessment retains its own configuration snapshot. Scope changes
require reauthorization and target revalidation.

## API usage

The interactive OpenAPI docs are at `http://127.0.0.1:8765/docs`. Writes require
both `Content-Type: application/json` and `X-WebScope-Request: workstation`.
GET requests do not trigger collection.

```sh
curl --fail http://127.0.0.1:8765/api/health
curl --fail http://127.0.0.1:8765/api/assessments
```

The API covers assessment create/read/update/archive/delete/validate/discover/
analyze/checks; all inventories; manual endpoint/OpenAPI import; graph; finding
review and notes; evidence and transaction detail; cases and notes; settings;
rule metadata; persisted report generation and download. Request/response
schemas are generated by FastAPI from Pydantic models.

## Coverage boundaries

WebScope does not log into applications, execute target JavaScript, run imported
POST/PUT/PATCH/DELETE operations, enumerate arbitrary paths, enumerate all
TLS ciphers/protocols, or map every page of a modern client-side app.
Use manually supplied endpoints/OpenAPI to augment a bounded surface.
No external intelligence service is configured or required.
